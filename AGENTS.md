# AGENTS.md

This file provides guidance to coding agents when working with code in this repository.

## Overview

Personal website (https://dedic.eu) built with SvelteKit 5 + Vite, prerendered to fully static output via `@sveltejs/adapter-static`. No server runtime — everything is generated at build time.

## Commands

- `npm start` — dev server (Vite, HTTPS via basic-ssl at https://127.0.0.1:5173)
- `npm run build` — production build to `dist/` (runs `clean` first)
- `npm run lint` — runs all linters in parallel: ESLint, Stylelint (CSS-in-Svelte), `svelte-check`, and `tsc` typechecks (app + config tsconfigs)
- `npm run lint:eslint -- --fix` — auto-fix ESLint issues **and formatting** (Prettier runs via `eslint-plugin-prettier`; do not run `prettier` directly)
- `npm run check` — post-build compatibility checks (CSS via doiuse, JS via es-check against es2022)
- `npm test` — Playwright tests inside the official Playwright Docker container (required for stable visual snapshots)
- `npm run test-native` — Playwright directly on host (snapshots will differ from CI/Docker)
- `npm run playwright-accept` — update visual snapshots (in Docker)
- `npm run playwright-interactive` — Playwright UI mode in Docker

To run a single test: `npm run test-native -- tests/navigation.spec.ts` (or add `-g "<title>"`). For committed snapshots, run via Docker instead.

## Architecture

- **Static prerender.** `svelte.config.js` uses adapter-static with `strict: true` and a `fallback.html`. A CSP is defined there in `hash` mode — inline scripts/styles must stay hashable. `origin` is exported from `svelte.config.js` and reused by `vite.config.js` for the sitemap.
- **CSS.** Vite uses LightningCSS as the transformer, with targets derived from `browserslist` (`baseline 2022`). Write modern CSS/SCSS; LightningCSS lowers syntax and adds prefixes down to the floor. Component styles live inside `.svelte` files and are linted by Stylelint.
- **Content as JSON.** Publications and teaching data live in `static/*.json` (`publications.json`, `teaching.json`) and are fetched at prerender time through `src/lib/utils/loadJsonConfig.ts` / `loadPublications.ts` using SvelteKit's `fetch`. Types are in `src/lib/types/`.
- **Routes.** `src/routes/` — top-level pages plus `blog/`, `publications/`, and `teaching/`. Teaching is organized as `teaching/<COURSE>/<term>/+page.svelte` (e.g. `TNN/2025-summer`), with `+page.server.ts` / `+layout.server.ts` loaders. `src/lib/utils/courseLists.ts` and `findCourseRoute.ts` drive course navigation.
- **Components.** Reusable UI in `src/lib/components/` (imported via the `$lib` alias), including math (KaTeX: `InlineMath`, `MathBlock`), code (`CodeBlock`/`InlineCode` via PrismJS, bibtex highlighting), and layout/navigation pieces.
- **`.htaccess`** is generated at build by `rollup-plugin-htaccess` (config in `rollup-plugin-htaccess.config.ts`); the sitemap is generated by `svelte-sitemap`.

## Conventions

- ESLint config (`eslint.config.js`) is strict and enforces `perfectionist` (sorted keys/imports), `prefer-arrow-functions`, `simple-import-sort`, and eslint-comments rules. Directives and preset warn-level rules are enforced at error severity — keep the tree clean.
- Prefer arrow functions; keep object keys and imports sorted (auto-fixable).
